## 1. Overview

This guide explains how data flows between the Warehouse Management System (WMS) and SAP ERP at MCG distribution centers. Understanding this integration is critical because **data discrepancies between these two systems are the #1 source of inventory inaccuracy** at MCG, currently resulting in a 74% inventory record accuracy (IRA) rate against a 97% target.

## 2. System Landscape

MCG operates two WMS platforms depending on region:

| Region | WMS | SAP Instance | Integration Method | Sync Frequency |
|---|---|---|---|---|
| Americas (US, Canada, Brazil) | Oracle WMS | SAP ECC 6.0 (Americas) | Batch interface (IDOC) | Every 15 minutes |
| Europe (NL, DE, FR, BE, UK) | Oracle WMS | SAP S/4HANA (EU) | Batch interface (BAPI) | Every 15 minutes |
| APAC (SG, MY, TH, AU) | Manhattan WMS | SAP ECC 6.0 (APAC) | Flat file (CSV) | Every 30 minutes |
| Africa (NG, GH, KE) | Manhattan WMS | SAP ECC 6.0 (APAC) | Flat file (CSV) | Every 60 minutes |

### 2.1 Critical Understanding: WMS is the Source of Truth for Physical Inventory

- **WMS** records what is physically in the warehouse (scan-based)
- **SAP** records what the enterprise system believes is in the warehouse (accounting-based)
- When these two systems disagree, **WMS is correct** (because it's based on physical scans)
- SAP is updated FROM WMS, not the other way around

### 2.2 Known Sync Delays

| Scenario | Expected Delay | Maximum Acceptable | Action if Exceeded |
|---|---|---|---|
| Goods receipt (WMS → SAP) | 15-30 minutes | 60 minutes | Contact IT Service Desk |
| Inventory adjustment (WMS → SAP) | 15-30 minutes | 60 minutes | Contact IT Service Desk |
| Pick confirmation (WMS → SAP) | 15 minutes | 30 minutes | Contact IT Service Desk |
| Transfer posting (SAP → WMS) | 15 minutes | 45 minutes | Contact IT Service Desk |

**IMPORTANT**: There is a known issue where the WMS-SAP batch job can fail **silently** without generating any error alerts. In September 2025, a batch job failure at the Rotterdam DC went undetected for **4.3 days**, creating 847 units of phantom inventory across 42 SKUs (see INC-2025-04872).

Until automated pipeline monitoring is implemented (Project CLARITY, Q1 2026), warehouse managers must perform a **daily manual sync check** (see Section 5).

## 3. Common Data Flow Scenarios

### 3.1 Goods Receipt

```
Truck arrives → WMS: RF scan at dock → WMS: Put-away scan → WMS creates receipt
                                                                    ↓
                                                            Batch job (15 min)
                                                                    ↓
                                                         SAP: Goods receipt posted
                                                         SAP: Inventory updated
                                                         SAP: PO updated (qty received)
```

**Key fields transferred**:
| WMS Field | SAP Field | Notes |
|---|---|---|
| Receipt ID | Material Document | Generated by SAP on posting |
| Item number | Material Number | Must match -- WMS uses MCG SKU |
| Quantity received | Quantity | Must match exactly |
| Lot number | Batch number | **CRITICAL**: Must be captured in WMS structured field, not comments |
| Storage location | Storage Location (LGORT) | Mapped via location master |
| Receipt timestamp | Posting date/time | **WARNING**: SAP posting time may differ from WMS scan time by 15-30 min |

**Common errors at this stage**:
1. **Lot number not scanned**: If the lot number barcode is unreadable, clerks sometimes type it into the WMS comments field. This does NOT transfer to SAP. Always use the designated lot number field.
2. **Quantity mismatch**: If a partial receipt is entered in WMS (e.g., 487 of 500 units due to damage), SAP will show the partial quantity. The PO remains open for the remaining 13 units. Do NOT create a second receipt for the missing units unless they physically arrive.

### 3.2 Inventory Adjustment

When a cycle count reveals a discrepancy:
```
Physical count → WMS: Count entered → WMS: Variance calculated
                                             ↓
                                      Variance > tolerance?
                                      ↓ Yes              ↓ No
                              WMS: Supervisor approval    WMS: Auto-adjusted
                                      ↓                         ↓
                              WMS: Adjustment posted      Batch job → SAP
                                      ↓
                              Batch job → SAP
```

**IMPORTANT**: SAP adjustments from cycle counts may take up to **45 minutes** to post because the supervisor approval step holds the WMS transaction. During this window, SAP will show the OLD quantity while WMS shows the NEW quantity. This is normal.

### 3.3 Pick and Ship

```
SAP: Sales order created → SAP: Delivery created → Batch job → WMS: Pick task created
                                                                        ↓
                                                               WMS: RF pick scan
                                                                        ↓
                                                               WMS: Pack station scan
                                                                        ↓
                                                               WMS: Ship confirmation
                                                                        ↓
                                                                Batch job (15 min)
                                                                        ↓
                                                              SAP: Goods issue posted
                                                              SAP: Inventory reduced
```

## 4. Timestamp Handling

**THIS IS A CRITICAL SECTION. READ CAREFULLY.**

MCG has a known issue with inconsistent timestamp handling across regions:

| System | Timestamp Format | Timezone Convention |
|---|---|---|
| Oracle WMS (EU) | `YYYY-MM-DD HH:MM:SS` | **CET (UTC+1) / CEST (UTC+2)** -- no timezone indicator stored |
| Oracle WMS (Americas) | `YYYY-MM-DD HH:MM:SS` | **Local time of DC** -- no timezone indicator stored |
| Manhattan WMS (APAC/Africa) | `YYYY-MM-DDTHH:MM:SS` | **UTC** -- but some DCs were configured for local time in error |
| SAP S/4HANA (EU) | `YYYYMMDD HHMMSS` | **UTC** |
| SAP ECC (Americas/APAC) | `YYYYMMDD HHMMSS` | **UTC** |

**Why this matters**: When you compare a WMS timestamp to a SAP timestamp, they may appear different even for the same event. For example:

> WMS goods receipt scan: `2025-09-18 11:45:00` (this is CET, i.e., UTC+1)
> SAP goods receipt posting: `20250918 134500` (this is UTC, plus ~30 min batch delay)

The actual time difference is only ~30 minutes (batch delay), but if you naively compare the numbers, it looks like a 2-hour gap. The Rotterdam DC incident report (INC-2025-04872) specifically notes a "2.5-hour timestamp discrepancy" that was caused by this timezone confusion.

**Rule of thumb**: Always convert WMS timestamps to UTC before comparing to SAP. Your DC's UTC offset is posted on the warehouse operations board.

## 5. Daily Manual Sync Check

Until Project CLARITY provides automated pipeline health monitoring, all warehouse managers must perform this check every morning:

### Step 1: Compare WMS and SAP transaction counts

1. Open WMS Report: Daily Transaction Summary (RPT-WMS-001)
2. Open SAP Transaction: MB51 (Material Document List)
3. Filter both for yesterday's date
4. Compare total transaction count:
   - WMS transactions should be ≤ SAP transactions (SAP may include non-WMS transactions)
   - If WMS count > SAP count by more than 5%, the batch job may have failed

### Step 2: Spot-check 5 random SKUs

1. Select 5 SKUs from different warehouse zones
2. Compare WMS on-hand quantity to SAP stock (transaction MMBE)
3. Quantities should match within batch sync window (30 min)
4. If any SKU shows a variance > 10 units, investigate

### Step 3: Check batch job status

1. Open SAP Transaction: SM37 (Job Overview)
2. Search for job name: `WMS_SYNC_*`
3. Verify status is "Finished" for all scheduled runs in past 24 hours
4. If any job shows "Cancelled" or "Released" (but not "Finished"), contact IT immediately

### Step 4: Log the check

Record your daily check in the Warehouse Operations Log (Excel file on shared drive: `\\mcg-file01\warehouse-ops\daily-checks\{DC-code}\{YYYY-MM}\`)

**NOTE**: Yes, we know this is a manual process using a shared Excel file. This is a temporary measure until the Qlik platform provides automated monitoring. We estimate this check takes 15-20 minutes per day.

## 7. Frequently Asked Questions

**Q: Why can't we just have real-time sync instead of batch?**
A: The current SAP-WMS interface was designed in 2018 when transaction volumes were lower. Real-time sync requires a different technical architecture. Project CLARITY will replace the batch interface with Change Data Capture (CDC) via Qlik Talend Cloud, providing near real-time sync (< 1 minute latency).

**Q: What happens if I enter data in SAP directly instead of WMS?**
A: Do NOT do this. SAP inventory changes that bypass WMS will create phantom inventory (SAP thinks we have stock that WMS doesn't know about). Always make physical inventory changes through WMS.

**Q: The lot number barcode is damaged. What do I do?**
A: Contact the supplier for the lot number. Do NOT leave the lot number blank or enter "N/A" -- this violates MCG-POL-007 (EU Food Safety Compliance). If you cannot obtain the lot number within 4 hours, escalate to the Quality team for disposition.

**Q: Manhattan WMS shows timestamps differently than Oracle WMS. Why?**
A: Different WMS platforms have different timestamp configurations. See Section 4 for the full breakdown. This is a known issue that will be resolved by the timestamp normalization pipeline in Project CLARITY.
